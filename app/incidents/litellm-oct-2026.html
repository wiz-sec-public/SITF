LiteLLM (October 2026): attack mapped to SITF techniques

Incident18 SITF techniques

This page maps the LiteLLM (October 2026) attack to the SDLC Infrastructure Threat Framework (SITF), step by step, from initial access to impact.

Organizations involved: BerriAI (LiteLLM producer); Downstream Consumers

Entry points

  • Stolen Credentials: Agent Platform admin key leaked 05-27, never revoked

Attack path

  1. SITF T-V003: Secret Exfiltration from Repo — opencode.json with admin key in public history (05-27 18:53) · in LiteLLM-Labs/lite-harness (public, sibling org)
  2. SITF T-P011: Steal Secrets from Production Environment — Agent Platform API returns an org owner's gh OAuth token (10-10 21:27) · in Internal LiteLLM Agent Platform
  3. SITF T-V001: Abuse Credentials for VCS Access — Owner, then maintainer #2/#3 gh tokens used (10-10 to 10-21) · in GitHub BerriAI org (litellm, project-releaser)
  4. SITF T-C005: Secret Exfiltration from Workflow — ci-tmp-* push workflows post secrets to webhook.site (10-10, 10-12) · in GitHub Actions: litellm repos + private release workflows
  5. SITF T-V010: Malicious Code Modification in Repository — 9cf97e9 adds source_owner input; owner token overrides branch protection (10:08) · in GitHub BerriAI org (litellm, project-releaser)
  6. SITF T-C001: Abuse Credentials for CI/CD Access — Owner token dispatches staging (10:46); maintainer #2 approves prod (11:11) · in GitHub Actions: litellm repos + private release workflows
  7. SITF T-C002: Malicious Execution in Workflow Context — Legitimate pipeline builds and signs from the lookalike fork · in GitHub Actions: litellm repos + private release workflows
  8. SITF T-R004: Publishing Malicious Package — litellm==1.107.0 (7 wheels + sdist) via Trusted Publishing, 11:39 · in PyPI, GHCR, Docker Hub
  9. SITF T-R005: Publishing Malicious Container/VM Image — Signed images v1.107.0, latest, main-latest, main-stable (11:46) · in PyPI, GHCR, Docker Hub
  10. SITF T-V008: Malicious Repo Hosting — Attacker preparation: lookalike fork Berri-AI/litellm (10-21 08:56-10:46) · in GitHub BerriAI org (litellm, project-releaser)
  11. SITF T-R012: Package Lifecycle Script Abuse — cook.pth + sitecustomize.py run on every Python interpreter start · in PyPI, GHCR, Docker Hub
  12. SITF T-V013: VCS Evidence Destruction — Run records deleted (10-10, 10-21); main reverted and force-pushed (12:09-12:24) · in GitHub BerriAI org (litellm, project-releaser)
  13. SITF T-E001: Malicious Execution on Endpoint — pip install litellm: cook.pth runs on every Python start · in Developer workstations
  14. SITF T-P011: Steal Secrets from Production Environment — Proxy DB dump: LiteLLM_CredentialsTable, LiteLLM_ProxyModelTable · in Consumer K8s nodes, LiteLLM proxies, AWS
  15. SITF T-C010: Runner Executing Malicious Package — Runners installing litellm 1.107.0 / pulling :latest execute payload · in Consumer CI runners
  16. SITF T-E003: Harvest Local Secrets / Credentials from Endpoint — Developer, cloud and AI-tool credentials harvested · in Developer workstations
  17. SITF T-C005: Secret Exfiltration from Workflow — Runner env, cloud, AI-tool credentials exfiltrated to litellm.dev · in Consumer CI runners
  18. SITF T-P007: Cloud Metadata Service Exploitation — AWS instance-role credentials from K8s nodes · in Consumer K8s nodes, LiteLLM proxies, AWS
  19. SITF T-E017: Legitimate Service Abuse for C2 — Hourly loader reads C2 domain from GitHub dead drop · in Developer workstations
  20. SITF T-P009: Cloud Service Lateral Movement — sts:GetCallerIdentity then Bedrock model listing (16:20-17:01Z) · in Consumer K8s nodes, LiteLLM proxies, AWS

Outcomes

  • Secondary Supply Chain Attack: Stolen CI/registry secrets from every litellm installer
  • Future Breach: LLMjacking via stolen cloud credentials; hourly RCE loader
