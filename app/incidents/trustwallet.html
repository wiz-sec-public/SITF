Trust Wallet: attack mapped to SITF techniques

Incident4 SITF techniques

This page maps the Trust Wallet attack to the SDLC Infrastructure Threat Framework (SITF), step by step, from initial access to impact.

Entry points

  • Previous breach

Attack path

  1. SITF T-R001: Abuse Credentials for Registry Access — Creds from shai-hulud-2 · in TrustWallet Chrome Web Store
  2. SITF T-R004: Publishing Malicious Package — Extension v2.8 · in TrustWallet Chrome Web Store
  3. SITF T-E001: Malicious Execution on Endpoint — Within browser · in Extension users
  4. SITF T-E003: Harvest Local Secrets / Credentials from Endpoint — in Extension users

Outcomes

  • Stolen funds

Techniques and controls

TechniqueKey protective controls
T-E001 Malicious Execution on EndpointLocal registry proxy with filtering; IDE sandboxing; Mandating signed extensions
T-E003 Harvest Local Secrets / Credentials from EndpointCredential manager enforcement; No production credentials on endpoints; Encrypted credential storage
T-R001 Abuse Credentials for Registry AccessMandatory MFA; IDP / SSO setup; CSPM/CNAPP
T-R004 Publishing Malicious PackageTrusted publishing; Provenance attestation; MFA for registry account
