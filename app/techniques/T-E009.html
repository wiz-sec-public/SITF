SITF technique T-E009: Abuse Local AI Tools

Component: Endpoint/IDEStage: Discovery and Lateral MovementID: T-E009

Attacker uses AI coding assistants to exfiltrate code or inject malicious suggestions.

SITF technique T-E009 (Abuse Local AI Tools) is a Discovery and Lateral Movement technique in the SDLC Infrastructure Threat Framework (SITF). It targets the Endpoint/IDE component (Developer workstations and development environments).

Risks that enable this technique

  • Using untrusted AI tools
  • No acceptable use policy
  • AI tools with excessive permissions
  • Sensitive code sent to AI services
  • AI tools signed in with personal accounts

Protective controls

  • Acceptable use policy against unapproved AI tools
    OWASP SPVS: V1.3 Security Requirements and Risk Assessment
  • Approved AI tools with data protection
    OWASP SPVS: V1.4 Developer Tool Operation
  • Code review for AI-generated code
    OWASP SPVS: V1.4 Developer Tool Operation; V2.3 Code Review and Analysis
  • Organization-managed (SSO) accounts enforced for AI tools — Require AI tools on managed endpoints to sign in with organization accounts, so code is only sent under an enterprise agreement with data protection and audit visibility
    OWASP SPVS: V1.1 Identity and Access Management

Detective controls

  • Network monitoring for AI service connections
    OWASP SPVS: V5.4 Detection & Monitoring
  • AI CLI execution with permission-bypass flags or non-interactive parent — EDR alerting when AI coding CLIs are launched with permission-bypass flags (e.g. --dangerously-skip-permissions, --yolo, --trust-all-tools) or spawned by package managers, install scripts, or other non-interactive processes
    OWASP SPVS: V5.4 Detection & Monitoring
  • AI agent tool-call audit logging via centrally managed hooks — Log AI agent tool calls (file reads, shell commands, network requests) at the hook or tool boundary and forward them to the SIEM; enforce hook configuration through managed policy so user and project settings cannot override it. An administrator on the endpoint can still remove hooks, so pair with network monitoring, which does not depend on the endpoint
    OWASP SPVS: V5.4 Detection & Monitoring
  • Alerting on suspicious AI agent tool-call sequences — Detect agent activity patterns such as a credential or secret file read followed by an outbound request
    OWASP SPVS: V5.4 Detection & Monitoring
  • AI tool signed in with an account outside the organization — Alert when an AI tool on a managed endpoint reports a signed-in account outside the organization's domain. The account is reported by the client, so this backs up SSO enforcement rather than replacing it
    OWASP SPVS: V5.4 Detection & Monitoring
