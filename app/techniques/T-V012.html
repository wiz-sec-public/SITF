SITF technique T-V012: Cross-Fork Object Reference Abuse

Component: VCSStage: Initial AccessID: T-V012

Attacker pushes malicious commits to a repository fork, exploiting git's shared object model to make those commits referenceable by SHA from the upstream repository without merging.

SITF technique T-V012 (Cross-Fork Object Reference Abuse) is a Initial Access technique in the SDLC Infrastructure Threat Framework (SITF). It targets the VCS component (Version Control Systems (GitHub, GitLab, Azure DevOps)).

Risks that enable this technique

  • No branch membership verification for SHAs
  • SHAs not validated against protected branches
  • Unrestricted forking on sensitive repos
  • No origin validation for fetched commits
  • No monitoring of non-branch commit references

Protective controls

  • SHA branch membership validation
    OWASP SPVS: V3.1 Security of Pipeline Environment; V3.3 Continuous Security Checks
  • Disable forking on sensitive repos
    OWASP SPVS: V1.5 Source Code Management Hardening
  • Signed commit enforcement
    OWASP SPVS: V1.5 Source Code Management Hardening; V3.4 Integrity of Artifacts
  • Action pinning with hash verification
    OWASP SPVS: V2.6 3rd Party Library Audit; V3.1 Security of Pipeline Environment

Detective controls

  • Workflow SHA provenance checks
    OWASP SPVS: V5.4 Detection & Monitoring
  • Fork push activity monitoring
    OWASP SPVS: V5.4 Detection & Monitoring
