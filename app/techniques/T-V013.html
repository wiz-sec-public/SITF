SITF technique T-V013: VCS Evidence Destruction

Component: VCSStage: Post-CompromiseID: T-V013

Attacker deletes workflow run records and rewrites protected branch history to remove evidence of malicious activity.

SITF technique T-V013 (VCS Evidence Destruction) is a Post-Compromise technique in the SDLC Infrastructure Threat Framework (SITF). It targets the VCS component (Version Control Systems (GitHub, GitLab, Azure DevOps)).

Risks that enable this technique

  • Any user with write access can delete workflow runs and logs
  • Admins can bypass force-push protection
  • Audit and workflow logs retained only in the VCS platform
  • No alerting on run deletion or history rewrites

Protective controls

  • Audit log streaming outside the VCS platform
    OWASP SPVS: V5.3 Secure Maintenance Practices; V5.4 Detection & Monitoring
  • Workflow log export to external storage
    OWASP SPVS: V3.1 Security of Pipeline Environment; V5.3 Secure Maintenance Practices
  • Force-push and deletion blocked with no bypass actors
    OWASP SPVS: V1.5 Source Code Management Hardening

Detective controls

  • Workflow run deletion alerting
    OWASP SPVS: V5.4 Detection & Monitoring
  • Protected branch history rewrite alerting
    OWASP SPVS: V5.4 Detection & Monitoring

Framework mappings
